## 三、初始化服务器

### 3.1 登录

ECS 控制台 → 实例 → 复制公网 IP，然后：

```bash
ssh root@你的公网IP
```

Ubuntu 镜像的默认用户就是 `root`，密码是创建实例时设的（忘了可以在控制台重置）。

### 3.2 装 Docker

```bash
# 用阿里云镜像源装，比官方源快很多
curl -fsSL https://get.docker.com | sh -s -- --mirror Aliyun

# 验证
docker --version
docker compose version
```

### 3.3 加 2G swap（2核4G 机器的保险）

4G 内存跑 MySQL + Redis + JVM 是够的，但突发流量或大数据量查询时可能瞬时超限。
加 swap 后系统不会直接 OOM Kill 掉进程，而是变慢——**变慢比崩溃好排查**。

```bash
fallocate -l 2G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab

# 验证
free -h
```

### 3.4 时区

```bash
timedatectl set-timezone Asia/Shanghai
```

## 四、拉代码并配置

### 4.1 拉代码

```bash
mkdir -p /opt && cd /opt
git clone https://github.com/xiaoluogende/askbase.git
cd askbase
```

### 4.2 配置密钥

```bash
cp .env.prod.example .env.prod
```

生成几个随机密码，把输出填进 `.env.prod`：

```bash
# MySQL root 密码
openssl rand -base64 18 | tr -d '/+=' | head -c 18; echo
# 应用数据库密码
openssl rand -base64 18 | tr -d '/+=' | head -c 18; echo
# Redis 密码
openssl rand -base64 18 | tr -d '/+=' | head -c 18; echo
# JWT 密钥（必须 ≥32 字节）
openssl rand -base64 48; echo
```

然后编辑：

```bash
vim .env.prod
```

逐项填好。**`MYSQL_ROOT_PASSWORD`、`DB_PASSWORD`、`REDIS_PASSWORD`、`JWT_SECRET`、`DEV_ADMIN_PASSWORD` 这五项必须改**，其余照抄模板即可。两个大模型 Key 从本地 `.env` 复制过去。

> 配置里用了 `${VAR:?提示}` 语法：变量没设就**启动失败**。
> 这是故意的——生产配置不能靠默认值蒙混过关。

## 五、启动

### 5.1 先解决拉镜像问题（国内必踩）

阿里云服务器拉 Docker Hub 通常不通。用镜像站全名拉再打 tag：

```bash
docker pull docker.m.daocloud.io/library/mysql:8.4
docker tag  docker.m.daocloud.io/library/mysql:8.4 mysql:8.4

docker pull docker.m.daocloud.io/redis/redis-stack-server:7.4.0-v0
docker tag  docker.m.daocloud.io/redis/redis-stack-server:7.4.0-v0 redis/redis-stack-server:7.4.0-v0
```

> 如果 daocloud 也不通，去阿里云「容器镜像服务 ACR」控制台开通，每个账号有专属加速地址，
> 配置到 `/etc/docker/daemon.json` 的 `registry-mirrors` 里，然后 `systemctl restart docker`。

### 5.2 构建并启动

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build
```

第一次会下载 Maven 依赖并编译，**大约 5–8 分钟**，别以为卡住了：

```bash
# 看构建进度
docker compose -f docker-compose.prod.yml --env-file .env.prod logs -f app
```

看到这行就成功了：

```
Started AskbaseApplication in 8.2 seconds
```

### 5.3 确认三个容器都健康

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod ps
```

期望：`mysql` 和 `redis` 是 `healthy`，`app` 是 `running`。

## 六、开放端口（安全组）

ECS 控制台 → 实例 → 安全组 → 配置规则 → 入方向 → 手动添加：

| 端口范围 | 授权对象 | 用途 |
|---|---|---|
| 22/22 | 你的公网 IP/32 | SSH |
| **8080/8080** | 0.0.0.0/0 | 应用 |

**只开这两个。** 千万不要开 3306（MySQL）和 6379（Redis）——
`docker-compose.prod.yml` 里已经刻意没有映射这两个端口，但如果你手贱加了映射再开放安全组，
等于把数据库直接摆在公网上。Redis 无密码暴露公网是全网扫描的头号目标，几小时内就会被挖矿程序接管。

## 八、常见问题

**Q：`docker compose up` 报 `必须 在 .env.prod 里设置`**
说明 `.env.prod` 里那个变量是空的。`${VAR:?提示}` 语法就是干这个的——故意让配置不全时启动失败，而不是带着空密码跑起来。

**Q：构建卡在 `mvn dependency:go-offline`**
国内下载 Maven 依赖慢。在 `pom.xml` 里加阿里云仓库，或者本地 `mvn package` 后 `scp` 上去（见第九节）。

**Q：浏览器打不开 8080**
① 安全组开了吗 ② 容器在跑吗（`docker compose ps`）③ 应用日志有报错吗（`logs app`）。
从服务器内部 `curl localhost:8080` 能通、外部不通，99% 是安全组。

**Q：日志里有 `Connection refused` 连 MySQL**
应用启动比 MySQL 快。`depends_on` 的 `condition: service_healthy` 已经处理了，但如果 MySQL 初始化失败（比如 SQL 有错），健康检查永远不会通过。看 `logs mysql`。

**Q：`/api/health/db` 返回 `studentCount: 0`**
`db/*.sql` 只在**数据卷为空**时执行一次。如果之前起过又改过 SQL，要 `down -v` 再起（会删数据）。

**Q：内存不够，进程被杀了**
`dmesg | grep -i "killed process"` 能看到。先加 swap，再考虑调小 `JAVA_OPTS` 的堆。

## 九、进阶：加速构建（可选）

服务器上编译一次 5–8 分钟，改代码后重新部署会很难受。两种优化：

**方案 A：本地构建后上传**

```bash
# 本地
mvn -B clean package -DskipTests
scp target/askbase-0.1.0-SNAPSHOT.jar root@你的IP:/opt/askbase/app.jar

# 服务器：把 docker-compose.prod.yml 里 app 的 build 换成 image 或挂载 jar
```

**方案 B：用阿里云镜像仓库缓存**

在 ACR 建仓库，本地 `docker build` 后 push，服务器直接 pull。适合反复部署。
