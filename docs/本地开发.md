## 一、启动前检查（30 秒）

```bash
cd F:/workbuddy/2026-10-21-16-42-20/Askbase

# 1. 容器在不在
docker compose --profile mysql ps
#    期望：askbase-mysql / askbase-redis 都是 healthy

# 2. .env 里的 Key 填了没
grep -c "API_KEY=sk-" .env
#    期望：2（两个都填了）。填 0 就是空的，问答功能用不了

# 3. 8080 有没有被占用
netstat -ano | grep ":8080.*LISTENING"
#    有输出说明已经有一个实例在跑，先停掉
```

容器没起：

```bash
docker compose --profile mysql up -d
```

## 二、三种启动方式

### 方式 A：IDEA 里点绿三角（日常最推荐）

打开 `src/main/java/com/askbase/AskbaseApplication.java`，点 `main` 方法左边的绿色三角。

**两个必须确认的设置**（改一次就行）：

| 位置 | 值 | 为什么 |
|---|---|---|
| Project Structure → SDK | **21** | pom 里写的是 21，用 17 编译不过 |
| Run Configuration → Working directory | **项目根目录** `Askbase/` | 应用要读根目录的 `.env`，工作目录错了就读不到 Key |

工作目录不对的表现：应用能起来，但一问问题就报"未配置对话模型 API Key"。

### 方式 B：命令行 `mvn spring-boot:run`

```bash
mvn spring-boot:run
```

⚠️ **如果它跑到一个奇怪的端口**（比如 4691、6764），说明环境里有东西在覆盖 `server.port`。
加上显式参数就好：

```bash
mvn spring-boot:run -Dspring-boot.run.arguments=--server.port=8080
```

### 方式 C：打包后 `java -jar`

```bash
mvn -B clean package -DskipTests
java -jar target/askbase-0.1.0-SNAPSHOT.jar --server.port=8080
```

这种方式最接近生产环境，排查"IDE 里能跑、打出来不能跑"时用它。

> **打之前先停掉正在跑的应用。** 否则 Windows 上 jar 文件被占用，
> `spring-boot:repackage` 会报 `Unable to rename ... .jar.original`，
> 然后生成一个没有主清单属性的坏 jar（报"没有主清单属性"）。

## 三、日常循环：改代码后怎么验证

```
改 Java 代码 → 重启应用（容器不用动）
改前端（static/） → 重启应用
改 db/*.sql → 必须重建数据卷（见第五节）
改 application.yml → 重启应用
```

**容器不用每次重启**，只有改了 SQL 才需要动。

前端改动想立刻看到效果，可以在 IDEA 里直接改 `target/classes/static/` 下的文件（会热更新），
但那是临时验证，最终以 `src/main/resources/static/` 为准。

## 四、常用命令

```bash
# 看容器状态
docker compose --profile mysql ps

# 看容器日志
docker compose --profile mysql logs -f mysql

# 只停应用（保留容器）
#   Windows：找到占用 8080 的 PID 再 kill
netstat -ano | grep ":8080.*LISTENING"
taskkill //PID <PID> //F

# 停容器（保留数据）
docker compose --profile mysql down

# 停容器 + 删数据（⚠️ 数据全没，下次启动会重新执行 db/*.sql）
docker compose --profile mysql down -v

# 进数据库看看
docker exec -it askbase-mysql mysql -uaskbase -p askbase
#   注意加 --default-character-set=utf8mb4，否则中文查询会失败

# 进 Redis
docker exec -it askbase-redis redis-cli

# 重建 Schema 索引（改了表注释或表结构后）
curl -X POST http://localhost:8080/api/schema/reindex \
  -H "Authorization: Bearer <token>"
```

## 五、什么时候必须 `down -v`

`db/*.sql` 只在**数据卷为空**时执行一次。以下情况必须重建：

- 改了 `db/schema.sql` / `db/schema_auth.sql` / `db/seed_sample.sql`
- 重新跑了 `python tools/gen_seed.py` 生成新数据
- 表结构和代码对不上（报 `Unknown column`）

```bash
docker compose --profile mysql down -v
docker compose --profile mysql up -d
# 等 healthcheck 变 healthy（约 30-40 秒）
```

**这是本地开发最容易卡住的地方**——改了 SQL 却没生效，会怀疑自己 SQL 写错了。

## 六、验证跑通了

```bash
# 1. 应用活着
curl -s http://localhost:8080/api/health

# 2. 数据库连得上（这条最重要，/api/health 证明不了）
curl -s http://localhost:8080/api/health/db
#    期望：tableCount 13, studentCount 375

# 3. 模型装配了（看启动日志）
#    期望有两行「对话模型已装配」「向量模型已装配」
```

浏览器打开 **http://localhost:8080**，账号 `admin`，密码看 `.env` 里的 `DEV_ADMIN_PASSWORD`（默认 `admin123`）。

问一句「一共有多少名学生？」，应该返回 375。

## 七、常见问题

**Q：应用起来了，但一问就报"未配置对话模型 API Key"**

`.env` 没被读到。三个可能：
1. 工作目录不是项目根（IDEA 里改 Run Configuration 的 Working directory）
2. `.env` 里 Key 是空的（`grep API_KEY .env` 看看）
3. 之前跑过 `cp .env.example .env` 把 Key 冲掉了

**Q：`/api/health/db` 返回 `studentCount: 0`**

数据没导入。`db/*.sql` 只在数据卷为空时执行，`down -v` 重建。

**Q：报 `Port 8080 was already in use`**

已经有一个实例在跑。`netstat -ano | grep ":8080.*LISTENING"` 找到 PID，`taskkill //PID xxx //F`。

**Q：报 `Port 4691 was already in use`（或者其他奇怪端口）**

环境里有人在覆盖 `server.port`。用 `-Dspring-boot.run.arguments=--server.port=8080` 显式指定。

**Q：改前端没生效**

浏览器缓存。`Ctrl + F5` 强制刷新，或者开 DevTools → Network → Disable cache。

**Q：`docker compose up` 拉镜像超时**

国内拉不到 Docker Hub。用镜像站全名拉再打 tag：

```bash
docker pull docker.m.daocloud.io/library/mysql:8.4
docker tag  docker.m.daocloud.io/library/mysql:8.4 mysql:8.4
```

**Q：中文查询返回空，但数据看着正常**

字符集问题。用 `docker exec` 进 MySQL 时必须带 `--default-character-set=utf8mb4`，
否则客户端按 latin1 解析，中文条件永远匹配不上。

## 八、想从头来一遍

```bash
# 1. 停掉所有东西
docker compose --profile mysql down -v

# 2. 清掉构建产物
mvn clean

# 3. 重新来
docker compose --profile mysql up -d
mvn spring-boot:run
```

`.env` 不用重新建（除非你把它删了，那就 `cp .env.example .env` 再填 Key）。
